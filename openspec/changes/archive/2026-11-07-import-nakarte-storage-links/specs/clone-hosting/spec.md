## MODIFIED Requirements

### Requirement: Своё хранилище треков

Клон SHALL сохранять и открывать ссылки `nktl=` через своё хранилище треков (capability `track-storage`), а не через `tracks.nakarte.me`. Ключ, которого нет в своём хранилище (ссылки, которые раздавал nakarte.me), SHALL читать сам Worker хранилища из `tracks.nakarte.me` и хранить копию у себя; браузер SHALL ходить только в своё хранилище.

#### Scenario: Copy link в клоне

- **WHEN** пользователь клона нажимает «Copy link» и открывает ссылку
- **THEN** запросы `POST` и `GET /track/{key}` уходят на Worker клона, а не на `tracks.nakarte.me`

#### Scenario: Ссылка nakarte.me с nktl

- **WHEN** пользователь открывает ссылку nakarte.me с `nktl={key}`, которого нет в своём хранилище
- **THEN** браузер запрашивает `GET /track/{key}` у Worker'а клона, Worker берёт трек из `tracks.nakarte.me`, трек открывается, а запросов браузера к `*.nakarte.me` нет

### Requirement: Без запросов к инфраструктуре автора

Приложение SHALL не делать сетевых запросов к `nakarte.me` и его поддоменам при работе всех функций: слои, панорамы, поиск, треки, ссылки, высоты. Адреса `nakarte.me` в разборе ссылок (импорт и поиск по ссылкам nakarte.me) запросами не являются и допустимы. Единственное исключение — Worker хранилища треков, который читает из `tracks.nakarte.me` ключ, которого нет у него самого (требование «Своё хранилище треков»).

#### Scenario: Сквозная проверка

- **WHEN** по очереди включаются все слои, открывается панорама Street View, строится трек с профилем высот, делается «Copy link» и открывается ссылка nakarte.me
- **THEN** в журнале сетевых запросов нет ни одного адреса `*.nakarte.me`
